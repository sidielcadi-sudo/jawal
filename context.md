# Jawal — Contexte projet

## Projet
SaaS multi-tenant de gestion scolaire (K-12 Maghreb, priorité Maroc). Next.js 15 + Prisma + Postgres 16 (RLS) + microservice Python (FastAPI + OR-Tools + FET) en Docker. FR/AR/RTL via next-intl.

- **S6 Présences** : vue admin, justifications, pointage personnel + retenues auto, fiche élève + vue famille.
- **S7 Inscriptions** : DRAFT→ACTIVE→WITHDRAWN + réinscription bulk.
- **S8 Emploi du temps** : slots, EDT classe/prof/salle, conflits, dispos + volume, print, overrides, ICS, solveur OR-Tools (mono/multi) + FET, contraintes paramétrables, multi-cycles, contraintes par classe.
- **S9 Bulletins PDF** : pipeline HTML autonome → Playwright/Chromium → PDF (élève + lot classe). `lib/bulletin-{data,html}.ts`, `lib/pdf.ts`.
- **S10 Espace parent (phase 1)** : portail `/[locale]/parent` cloisonné (flag `isParent`), enfants via `lib/parent.ts`, bulletins/présences/scolarité, annonces, messagerie parent↔école (réutilise la messagerie admin participant-based), changement de mot de passe, historique multi-années. Provisioning depuis la fiche PARENT (+ email mdp temporaire via Mailpit). Compte démo `hassan.benani@demo.jawal.ma` / `parent1234`.
- **S11 Documents auto** : 4 PDF officiels (certificat scolarité, attestations présence/paiement/réussite) via le pipeline S9. `lib/document-{data,html}.ts`, `components/documents-panel.tsx`, routes admin + parent.

Moyenne matière + distribution (jauge + histogramme), présence + retards, charge horaire + quota, messages non lus ; programme/incidents/feedback en N/A. `lib/kpi-teacher.ts`.
- **Portail enseignant** : `/[locale]/enseignant` cloisonné (flag `isTeacher`, rôle `enseignant`). Tableau de bord (réutilise la vue), EDT (grille), mes classes, messagerie (réponse seule, participant), changement de mot de passe. Provisioning depuis la fiche prof (+ email). Modèle `PasswordResetToken` (SHA-256 du jeton, usage unique, TTL 1 h, dans RLS). Émission réservée aux comptes rôle `parent` via `prismaAdmin` (cross-tenant comme le login), e-mail Mailpit, anti-énumération (réponse générique). Lien sur le login. `lib/password-reset.ts`. - **Nomenclature services personnel** : enum `StaffService` + champ `Person.service` (STAFF). 11 services (direction, vie scolaire, comptabilité, services généraux…) dans `@jawal/shared` (`STAFF_SERVICES`). Sélecteur sur la fiche (STAFF), filtre sur la liste personnel, affichage fiche + badge liste. FR/AR.
- **Cahier de texte (Phase 1)** : modèles `LessonEntry` (cahier d'une séance = `TimetableEntry` × `date`, unique) + `Homework` (devoir lié à une séance) ; enums `HomeworkType`/`HomeworkDifficulty` ; dans RLS. **Saisie prof** : `/enseignant/cahier` (vue semaine datée lun→sam depuis l'EDT, statut rempli/à remplir) → `/enseignant/cahier/[entryId]/[date]` (infos séance auto + contenu cours + devoirs + visibilité élèves/parents). Garde-fous : seul le prof de la séance édite, date doit tomber le bon jour. **Consultation parent** : `/parent/cahier` (par enfant : devoirs à venir + leçons récentes, `visibleToParents`). `lib/lesson-book.ts`, schémas `@jawal/shared`. Pas de portail élève (flag `visibleToStudents` stocké, sans canal). **Phase 2 livrée** : pièces jointes (modèle `LessonResource` kind FILE/LINK ; fichiers S3 via `FileObject` ownerType `lesson.resource` ; upload route `/api/enseignant/cahier/[entryId]/[date]/resource`, download contrôlé `/api/cahier/resource/[id]` via `resolveResourceForDownload`, actions add-link/delete) + **visibilité programmée** (`LessonEntry.publishAt` ; masqué parents tant que non atteint ; filtre `parentVisibleWhere`). **Phase 3a livrée** : rappels séances non remplies — `getUnfilledSessionsForTeacher` (séances passées 14 j sans cahier, hors annulées) → bandeau d'alerte sur `/enseignant/cahier` ; cron `/api/cron/cahier-reminders` (`lib/cahier-reminders.ts`, auth `X-Cron-Secret`=AUTH_SECRET ou session) → e-mail digest par enseignant (Mailpit en dev). **Reste P3** : historique/versioning (3c), stats proviseur taux de remplissage (3b), compétences Massar (3d).
- **Enquêtes de satisfaction** : modèles `Survey`/`SurveyQuestion`/`SurveyResponse`/`SurveyAnswer` (enums audience/status/type ; questions RATING_5 + TEXT ; anonyme avec anti-doublon ; dans RLS). Admin `/admin/surveys` (liste, création multi-questions, diffusion/clôture, résultats agrégés : moyenne /5 + distribution + verbatims). Collecte côté **portail parent** `/parent/surveys` (réponse une fois, étoiles 1–5). KPI **satisfaction** du Pilotage branché via `computeSatisfaction` (moyenne RATING_5 des enquêtes OPEN/CLOSED, filtre période). `lib/survey.ts`, schémas `@jawal/shared`. Gating `communication.write`.

## Solveur EDT
- Docker Compose : `solver` sur `localhost:8001` (FastAPI + OR-Tools CP-SAT + FET 7.0.8). Endpoints `/solve`, `/solve-multi`, `/engines`.
- `forbidden_class_slots` calculés depuis Tenant.settings.timetable et Cycle.settings.timetable (multi-cycles). Contraintes par classe : Class.metadata.timetableConstraints.
- Contraintes `TimetableConstraint` (enum kinds) → `ConstraintsInput` : max même matière/jour, anti-trous, blocs consécutifs, max h/jour prof, **max consécutives prof (4E3)**, **pause déjeuner échelonnée (4E3)**, **type de salle obligatoire (4E4, heuristique `classifyRoom`/`subjectRoomRequirement`)**, **min. changements de salle + équilibrage journées (4E5, mous)**.
- FET excelle anti-trous. Les contraintes 4E3-4E5 ne s'appliquent qu'au moteur OR-Tools.
- **Affectations / génération** : le solveur dérive la liste des profs **uniquement** des `TeacherAssignment` (matière×classe×année) — pas des heures contractuelles ni des séances. Le générateur fait le *scheduling*, pas l'*allocation* (qui enseigne quoi). **Auto-affectation (Étape 1 faite)** : champ **« Classes prioritaires »** sur la fiche prof (pavé Compétences) → modèle `TeacherPriorityClass` (prof×classe, dans RLS), saisi via multi-picker (comme spécialités/cycles), affiché sur la fiche. **Étape 2 livrée** : moteur `lib/teacher-allocation.ts` — `proposeAllocation` (programme `CurriculumSubject` × `TeacherSpecialty` × heures contractuelles, **priorité aux `TeacherPriorityClass`**, équilibrage de charge ; lecture seule ; respecte les affectations existantes = épinglées ; motifs PINNED/PRIORITY/BALANCED/NO_SPECIALIST/OVER_CAPACITY) + `applyAllocation` (createMany skipDuplicates). UI : panneau **« Pré-affecter automatiquement »** sur `/admin/timetable/generate` (aperçu éditable par ligne + charge par prof + alertes) → `proposeAllocationAction`/`applyAllocationAction` → puis « Générer l'EDT ». Cases de classes sans affectation désormais sélectionnables (déblocage œuf-poule).
